## 1. 两套界面并存

| 入口 | 模块 | 说明 |
|---|---|---|
| `python -m triniscan.ui`（默认） | `ui/app_v2.py` | **工作台界面**（新） |
| `python -m triniscan.ui --ui classic` | `ui/app.py` | 原两页界面，保留作回退 |

选择逻辑在 `ui/__main__.py`，只有一行分派，两套界面互不 import：

```python
if args.ui == "classic":
    from .app import launch as _launch
else:
    from .app_v2 import launch as _launch
```

保留旧界面的理由：现场出问题时可以一条命令切回可用的界面，
而不是回退代码。

## 2. 工作台模型

### 2.1 为什么不是"更多页签"

旧界面只有两页（测量 / 标定），靠顶部单选按钮 + `place()` 叠放切换。
每加一个功能就要在主窗口加一个 `_page_xxx` 字段、一条 `lift/lower`
分支、以及 `on_hide` 的特殊处理。页数一多就失控。

新界面把**一个完整的操作场景**封装成一个 `Workbench`：

```
┌──────────────────────────────────────────────────────────────┐
│ 菜单：文件 / 视图 / 工具 / 帮助                                │
├──────────────────────────────────────────────────────────────┤
│ 工作台：[测量 ▼]                          状态：已加载标定     │  ← 顶栏
├────────────────────┬─────────────────────────────────────────┤
│ 左侧：可折叠面板    │ 右侧：主视图（页面互斥显示）              │
│  ▾ 相机            │                                         │
│  ▾ 扫描计划        │      实时画面   或   重建结果            │
│  ▸ 提取            │                                         │
│  ...               │                                         │
├────────────────────┴─────────────────────────────────────────┤
│ 底部工具条（由工作台自行填充）                                 │
└──────────────────────────────────────────────────────────────┘
│ 运行日志（可折叠）                                             │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 基类契约（`ui/workbench.py`）

子类只**声明有什么**，基类负责布局、滚动、挂载与生命周期：

```python
class SomeWorkbench(Workbench):
    title = "测量"
    panel_width = 360

    def add_panels(self):
        self.add_panel("camera", CameraPanel, expanded=True)
        self.add_panel("extract", ExtractPanel, expanded=False)

    def add_pages(self):
        self.add_page("main", VideoView(self.view_parent))

    def on_show(self): ...      # 进入本工作台
    def on_hide(self): ...      # 离开本工作台
```

| 成员 | 作用 |
|---|---|
| `add_panel(key, factory, expanded=)` | 左侧折叠面板，`factory(parent, workbench)` |
| `add_page(key, widget, show=)` | 右侧互斥视图 |
| `show_page(key)` | 切换右侧视图 |
| `panel(key)` | 取回面板实例 |
| `add_toolbar()` | 取到底部工具条容器 |
| `view_parent` | **右侧视图的父容器** |
| `set_logger(fn)` | 注入日志出口（主窗口提供） |

### 2.3 两个布局陷阱（已修复，勿回退）

**（A）pack 顺序决定谁被挤掉。**
`pack` 按调用顺序从剩余空腔中分配空间。若先 pack 带 `expand=True` 的
右视图，它会吃掉全部空间，底部工具条退化为 1×1 像素——按钮整排消失。
当前顺序是 **工具条 → 左侧面板 → 右视图**，注释写在
`Workbench._build()` 里。

**（B）右侧视图的 master 必须是 `view_parent`。**
`add_page()` 用 `place(relwidth=1, relheight=1)` 相对**父容器**铺满。
若视图的 master 是工作台根，它会盖住左侧面板与工具条。因此：

- `_right` 在 `Workbench.__init__` 中**先于**子类构造视图创建；
- 子类在 `add_pages()` 里用 `self.view_parent` 构造视图；
- `add_page()` 对 master 不符直接抛 `ValueError`，不静默降级。

## 3. 三个工作台

### 3.1 测量台（`workbench_measure.py`）

左侧面板与流水线的**一一对应**关系（每个面板都必须真正被 pipeline 读取）：

| 面板 | 读取点 |
|---|---|
| 相机 | `Camera(cfg.raw["camera"])` |
| 扫描计划 | `acquire` → `resolve_scan_plan(cfg)` |
| 提取 | `reconstruct_views` → `centerline_view(cfg)` |
| 过滤链 | `build_pointcloud` → `_run_filter_chain` |
| 配准 | `build_pointcloud` → `SEQUENTIAL_SPEC.read(cfg)` |
| 网格 | `measure_volume` → `POISSON_SPEC.read(cfg)` |
| 封闭 | `measure_volume` → `CLOSE_SPEC.read(cfg)` |
| 体积 | `measure_volume` → `volume.method` / 两个 spec |

> 网格面板**不提供** poisson/ball_pivoting 下拉：`measure_volume` 固定
> 调用 `POISSON_SPEC`，给出下拉就是假开关。面板以文字说明。

底部工具条：

```
[▶ 开始测量] │ [▶ 预览/■ 停止] ☑中心线 │ [显示画面][显示结果] │
图像上限 [___]（空=全部） │ [⚙ 从图像重建]            12.3 fps
```

| 控件 | 行为 |
|---|---|
| **▶ 开始测量** | **完整测量**：归零 → 逐视角转动/抓图 → 重建 → 体积。需要相机与转台 |
| ▶ 预览 / ■ 停止 | 实时取景，叠加激光中心线 |
| 中心线 | 叠加层开关 |
| 显示画面 / 显示结果 | 右侧两页互斥切换 |
| 图像上限 | 调试用，只处理前 N 张（`文件按名排序` 后的前 N 个） |
| **⚙ 从图像重建** | **跳过采集**，直接用 `output.raw_dir`（或指定目录）里的图像跑后半段 |

两个入口的区别：

| | ▶ 开始测量 | ⚙ 从图像重建 |
|---|---|---|
| 需要硬件 | 是 | 否 |
| 数据来源 | 现场采集 | 已有图像目录 |
| 流水线 | `acquire → reconstruct → build → volume` | `reconstruct → build → volume` |
| 适用 | 正式测量 | 调参、复现、无硬件环境 |

两条路径**共用同一套 pipeline 方法**（`RebuildJob` 只跳过 `acquire`），
因此"界面里跑出来的结果"与命令行一致。

### 3.2 标定台（`workbench_calib.py`）

**包装**而非重写 `ui/calibration.py`：拍摄节奏、质量判定、球心/棋盘格
两套转轴标定的实战逻辑全部保留，只补三个缺陷：

| 缺陷 | 原因 | 修法 |
|---|---|---|
| 无界队列 | 相机 30 fps 写入，UI 只取最新帧 → 十分钟堆积上万帧 | `LatestFrameQueue`（单槽位，丢旧留新） |
| 预览慢 | 内嵌 matplotlib 逐帧重绘 | `VideoView`（cv2 缩放 + PPM 交给 Tk，见 `video.py` 注释中的实测对比） |
| 标定失效无人知 | 改内参后激光/转轴标定不再成立，界面仍显示"已标定" | 顶部状态卡比对 `camera_md5` |

左侧面板：`status`（标定状态卡，展开）、`summary`（标定摘要，收起）；
右侧为标定主面板（`_CalibrationPanelV2`）。

### 3.3 硬件台（`workbench_hardware.py`）

四条设计约束：

1. **串口操作离开 UI 线程**——`serial` 读写在无响应时会阻塞到
   `timeout_s`，直接写在按钮回调里会让界面假死。复用 `Worker`。
2. **控件状态由连接状态驱动**——未连接时动作按钮 disabled；急停例外，
   连接后**始终可用**。
3. **误差可见**——转台只能执行整数微步，输入 37.3° 的实际到位角度与
   理论值有偏差；分度扫描会打印"指令步数 → 实际角度"。
4. **单任务互斥**——转台是单线程设备，上一动作未完成时忽略新指令
   （急停除外），否则串口指令交错。

面板：`conn`（连接参数 + 连接/断开）、`motion`（相对转动、转到、
归零、±90°、±10°、+180°、急停）、`scan`（分度扫描，预设 6/8/12/16/
24/36/72 站，硬上限 360 步）。右侧为状态页（角度、状态、忙闲）。

## 4. 参数表：单一来源

### 4.1 三条数据流

```
config/default.yaml ──► ConfigStore ──► FieldSpec ──► 控件
        ▲                    │              ▲
        │                    │              │ 算法 ParamSpec
        └──── 保存（原子写） ─┘        （默认值/范围/候选值）
```

| 模块 | 职责 |
|---|---|
| `ui/field_spec.py` | 把"配置树 + 算法 ParamSpec"合成为统一的字段描述 |
| `ui/params.py` | 按 `FieldSpec` 自动生成控件（`SpecPanel` / `ParamGroup` / `DictGroup`） |
| `ui/labels.py` | 中文标签与说明（唯一文案来源） |
| `ui/algorithm_panel.py` | 算法选择卡：只显示该实现声明的参数 |
| `ui/filter_chain_ui.py` | `reconstruction.filter_chain` 的可视化编辑 |

收益：默认值单一来源（`ParamSpec`），越界立即报错，UI 可枚举实现。
**新增配置项时只改 yaml + 算法 `ParamSpec` + `labels`，不需要碰控件代码。**

### 4.2 结构型配置

`filter_chain`（列表）、`scan` 等结构型配置在表里显示为
"（结构型，需专用编辑器）"而不是把整段字典灌进输入框。它们由专用
面板（`FilterChainEditor`、`ScanPanel`）编辑。

## 5. 后台任务与进度

所有耗时操作走 `ui/worker.py`：

```
UI 线程 ── Worker(fn).start() ──► 后台线程执行 fn
   ▲                                     │
   │  after(100~120ms) 轮询              │  queue.put(TaskMessage)
   └──────────── queue.Queue ◄───────────┘
```

| 消息类型 | 含义 |
|---|---|
| `progress` | 阶段 + 0~1 进度 + 文案 |
| `done` | 结果对象 |
| `error` | 异常文本 |

**规则**：后台线程只写队列，绝不碰控件。任何 `widget.configure()` 出现
在工作线程里都是 bug。

`RebuildJob` 的阶段权重（进度按权重累加，长阶段推进更快：

```
读取图像 10% → 提取+三角 45% → 配准+过滤 25% → 网格+体积 20%
```

## 6. 标定状态与新鲜度

`triniscan/calib_manifest.py` 负责回答"现在这套标定还能用吗"：

- 每个标定文件记录**生成时的相机内参指纹**（`camera_md5`）；
- 激光平面建立在相机内参之上（像素→射线），转轴建立在两者之上；
- 内参变了而激光/转轴还是旧的 → 状态卡标红，提示重标。

`CalibrationStatus` 由 `inspect_calibrations()` 计算，UI 只负责渲染，
判定逻辑不写在界面里（可单测）。

## 7. 操作流程

### 7.1 首次使用

1. 编辑 `software/config/default.yaml`（或界面参数面板）：相机 `index`、
   `backend`、`port`、转台参数；
2. 顶部切到 **硬件** → 「连接转台」→ 试 `+90°`，确认方向与回零；
3. 切到 **标定** → 依次做相机内参、激光平面、转轴，状态卡全绿；
4. 切到 **测量** → 「▶ 预览」确认激光线在画面里、曝光不过曝；
5. 「▶ 开始测量」。

### 7.2 日常测量

```
测量台 → ▶ 预览（确认画面）
       → ▶ 开始测量（自动：归零 → 720 视角采集 → 重建 → 体积）
       → 看"显示结果"页：体积、体素校核、阶段耗时、水密性
```

采集阶段有进度与预计剩余时间；全程无需干预。

### 7.3 只调算法参数

```
改参数（左侧面板）
 → ⚙ 从图像重建（复用 data/raw，跳过硬件）
 → 看结果页对比
 → 满意后 💾 保存配置
```

用「图像上限」填 20~50，可以把一轮迭代从几分钟压到几秒。

## 8. 扩展一个新的工作台

1. 新建 `ui/workbench_xxx.py`，继承 `Workbench`，设 `title` / `panel_width`；
2. 实现 `add_panels()` / `add_pages()`（视图用 `self.view_parent` 构造）；
3. 需要工具条就调 `add_toolbar()`；
4. 在 `app_v2.WORKBENCHES` 元组里追加，**顺序即下拉框顺序**；
5. 需要进出回调就实现 `on_show()` / `on_hide()`（例如开关相机）。

不需要改主窗口：`app_v2` 只做容器、菜单、状态栏与日志。
