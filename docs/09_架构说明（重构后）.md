# 软件架构说明（重构后）

> 本文描述 `software/triniscan` 的**当前**结构。若你读到的是旧版
> `03_软件架构设计.md`，以本文为准（那份描述的是重构前的形态）。

## 1. 分层

```
contracts/      契约层  ← 谁都依赖它，它不依赖任何人（只 import numpy）
   ↑
common/         纯工具（几何 / IO / 日志 / 稳健拟合）
   ↑
algorithms/     可插拔实现（每个域一个子包）
   ↑
pipeline/       编排（stages + 配置）
   ↑
core/ ui/ tools/ hardware/   应用入口
```

依赖方向**永远向上**，`contracts` 不允许 import 任何项目内其它包。
这保证了不会出现循环依赖，也让 `contracts` 的导入耗时保持在毫秒级。

## 2. contracts：四件契约

| 模块 | 提供 | 解决的原问题 |
|---|---|---|
| `plugin.py` | `Plugin` 协议、`PluginBase`、`RunContext` | 5 个环节 5 种调用签名，无法统一遍历 |
| `frames.py` | `ViewFrame`、`Cloud`、`CalibrationBundle` | 裸数组传参会"把相机系点当世界系过滤" |
| `report.py` | `MaskStack`、`StageReport`、`ScanReport` | 过滤删了多少、为什么删，完全不可见 |
| `params.py` | `ParamSpec` | 默认值散落各处，越界值静默通过 |
| `algorithm.py` | `AlgorithmSpec` | 纯函数型算法无法被枚举/校验 |
| `registry.py` | 7 张注册表 | `if method == ...` 分支散落 |

### 2.1 两种可插拔性

**（A）过滤器 = 插件对象**

过滤器需要共享上下文（标定、掩膜栈、报告），因此做成对象：

```python
class DepthFilter(FilterPlugin):
    name = "depth"
    params = (ParamSpec(...),)
    def compute_mask(self, cloud, ctx) -> (mask, info): ...
```

它们**只产出掩膜**，由 `FilterChain` 统一管理原始索引：

```python
chain = FilterChain.from_config(cfg)
cloud, masks = chain.apply(cloud, ctx)
print(masks.summary())
```

**（B）其余算法 = 声明式 spec**

提取/三角测量/配准/网格/封闭/体积是无状态纯函数，签名稳定。给它们
加 `AlgorithmSpec`（注册名 + 参数声明 + 函数引用），**函数本身不改**：

```python
spec = MESHERS.spec("poisson")
kw = spec.read(cfg)          # 读配置 + 类型转换 + 范围校验 + 回填默认值
mesh = reconstruct_mesh(pcd, **kw)
```

收益：默认值单一来源、UI 可枚举、越界立即报错。
代价：零——没有为它们新增任何转发类。

### 3.1 过滤链的顺序敏感性

| 过滤器 | 顺序敏感 | 原因 |
|---|---|---|
| `depth` | 否 | 只看点自身深度 |
| `bounds` | 否 | 只看点自身坐标 |
| `cluster` | 否 | 只看点间距离 |
| `statistical` | 否 | 只看邻域距离（默认关闭） |
| `turntable` | **是** | 依赖当前点云估计台面高度 |
| `axial` | **是** | 依赖当前点云的高度直方图 |

"顺序敏感"的层会在 `MaskStack` 里标 `depends_on_previous=True`，
UI 表里显示"是"，调换顺序时需要重新评估。

## 4. 配置

`config/default.yaml` 支持两种写法，**两者等价**：

```yaml
# 旧式（扁平开关）——仍然有效，行为逐字不变
reconstruction:
  depth_filter: true
  cluster_filter: true
  remove_turntable: true
  axial: {auto_trim: true}
```

```yaml
# 新式（显式链路）——推荐，能逐项覆盖参数
reconstruction:
  filter_chain:
    - {name: depth}
    - {name: cluster, eps_m: 0.003}      # 就地覆盖
    - {name: turntable, method: axis_height}
    - {name: axial, auto_trim: true}
```

判断规则：写了 `filter_chain` 就用它；没写就按旧键生成长度相同的链
（见 `filtering/base.py::_legacy_chain`）。

## 5. 可观测性

一次扫描产出的报告包含：

- `ScanResult.filter_layers`：每层过滤的结构化摘要
  （`name / applied / removed / removed_ratio / reason / depends_on_previous`）
- `ScanResult.filter_summary`：人可读表格（`MaskStack.summary()`）
- `ScanResult.calib_fingerprint`：标定指纹。**同一指纹下两次扫描的
  差异才是算法差异**；换标定后结果变了不是"算法不稳定"
- `StageReport.elapsed_s / params / warnings / fallbacks`

UI 的"过滤诊断"表直接渲染 `filter_layers`，删除率 ≥15% 标红。

## 6. 兼容层

迁移期间保留了一组 shim，旧路径全部可用：

```
triniscan.calibration.*      → algorithms/calibration/*
triniscan.camera.*           → hardware.camera
triniscan.turntable.*        → hardware.turntable
triniscan.extraction.*       → algorithms/extraction/*
triniscan.reconstruction.*   → algorithms/{features,registration,meshing,filtering}/*
triniscan.volume.*           → algorithms/{closing,volumetry}/*
core.pipeline._dominant_band → algorithms.filtering.dominant_band
ScanPipeline._filter_bounds / _filter_clusters /
_remove_turntable / _clip_axial_band → 对应过滤器插件
```

**新代码请直接使用 `algorithms.*`。** shim 的存在只为不破坏既有调用方。
